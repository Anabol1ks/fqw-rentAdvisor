# Resilient Yandex Scraper

Улучшенная версия скрапера недвижимости с Yandex.Realty с функциями надежности и восстановления после ошибок.

## Ключевые улучшения

### 🛡️ Механизмы надежности
- **Exponential Backoff**: Умная задержка с увеличением времени между попытками
- **Adaptive Retry Logic**: Автоматический повтор неудачных запросов
- **Captcha Detection & Recovery**: Обнаружение капчи и автоматическое ожидание
- **Protective Mode**: Замедление при большом количестве ошибок
- **Session Recovery**: Восстановление сессии после критических ошибок

### 🔄 Ротация и маскировка
- **User-Agent Rotation**: Автоматическая смена User-Agent
- **Proxy Rotation**: Поддержка ротации прокси-серверов
- **Dynamic Headers**: Динамическая настройка HTTP-заголовков
- **Request Fingerprinting**: Минимизация следов автоматизации

### 📊 Мониторинг и прогресс
- **Progress Saving**: Сохранение прогресса для восстановления
- **Detailed Statistics**: Подробная статистика работы
- **Error Analytics**: Анализ типов ошибок и частоты
- **Performance Metrics**: Метрики производительности

## Быстрый запуск

### 1. Автоматический режим (рекомендуется)
```bash
# Запуск с мониторингом и автоматическим перезапуском
monitor_scraper.bat
```

### 2. Ручной запуск
```bash
# Сборка и запуск с оптимальными настройками
run_resilient_scraper.bat
```

### 3. Настройка параметров
Отредактируйте файл `.env.resilient`:
```env
CITY=moskva
MAX_ITEMS=1000
PAGES=100
PARALLELISM=2
CAPTCHA_COOLDOWN=10m
ERROR_THRESHOLD=10
```

## Параметры командной строки

### Основные параметры
- `-city` - Город для скрапинга (moskva, peterburg, etc.)
- `-max-items` - Максимальное количество новых записей (0 = без лимита)
- `-pages` - Количество страниц для обхода
- `-deal` - Тип сделки (sale/rent)

### Resilient параметры
- `-max-retries` - Максимальное количество попыток для каждого URL (по умолчанию: 5)
- `-captcha-cooldown` - Пауза после обнаружения капчи (по умолчанию: 10m)
- `-error-threshold` - Количество ошибок для активации защитного режима (по умолчанию: 10)
- `-protective-delay` - Задержка в защитном режиме (по умолчанию: 30s)
- `-recovery-delay` - Пауза для восстановления сессии (по умолчанию: 2m)

### Маскировка и обход
- `-user-agent-rotation` - Включить ротацию User-Agent
- `-use-referer` - Включить заголовок Referer
- `-proxy` - HTTP/HTTPS прокси
- `-cookie` - Cookie для realty.yandex.ru

## Примеры использования

### Сбор объявлений о продаже в Москве
```bash
scrape_yandex.exe -city=moskva -deal=sale -max-items=500 -pages=50
```

### Сбор аренды в СПб с прокси
```bash
scrape_yandex.exe -city=peterburg -deal=rent -proxy=http://proxy:8080 -max-items=300
```

### Агрессивный режим с максимальной надежностью
```bash
scrape_yandex.exe -city=moskva -max-retries=10 -captcha-cooldown=15m -error-threshold=5 -protective-delay=60s
```

### Использование с переменными окружения
```bash
# Установка прокси
set PROXY_LIST=http://proxy1:8080,http://proxy2:8080,http://proxy3:8080

# Установка cookie
set COOKIE="session_id=...; auth_token=..."

# Запуск
scrape_yandex.exe -city=moskva -max-items=1000
```

## Обработка ошибок и восстановление

### Автоматическое восстановление после капчи
При обнаружении капчи скрапер:
1. Останавливает текущие запросы
2. Ждет указанное время (captcha-cooldown)
3. Автоматически возобновляет работу
4. При необходимости ротирует прокси/User-Agent

### Защитный режим
При большом количестве ошибок подряд:
1. Активируется защитный режим
2. Увеличиваются задержки между запросами
3. Снижается параллелизм
4. При нормализации - возврат к обычному режиму

### Сохранение прогресса
Скрапер автоматически сохраняет прогресс:
- Текущая страница
- Количество собранных элементов
- Статистика запросов
- Состояние retry для URL

## Мониторинг и логирование

### Лог-файлы
- `scraper.log` - Основной лог с детальной информацией
- `progress/*.json` - Файлы прогресса для восстановления

### Ключевые метрики
- **Success Rate** - Процент успешных запросов
- **Items/Hour** - Производительность сбора
- **Retry Rate** - Частота повторных попыток
- **Captcha Encounters** - Количество обнаружений капчи

### Анализ производительности
```bash
# Просмотр статистики сессии
findstr "scraping session completed" scraper.log

# Анализ ошибок
findstr "error\|failed" scraper.log | findstr /v "debug"

# Подсчет успешных записей
findstr "inserted new" scraper.log | find /c /v ""
```


## Устранение неполадок

### Частые капчи
- Увеличьте `captcha-cooldown`
- Уменьшите `parallelism`
- Увеличьте задержки между запросами
- Используйте ротацию прокси

### Низкая производительность
- Проверьте скорость сети
- Уменьшите задержки (осторожно!)
- Увеличьте параллелизм
- Используйте быстрые прокси

### Ошибки базы данных
- Проверьте подключение к PostgreSQL
- Убедитесь в корректности строки подключения
- Проверьте права доступа

### Ошибки памяти
- Уменьшите параллелизм
- Увеличьте лимит памяти для Go
- Периодически перезапускайте скрапер

## Лучшие практики

1. **Начинайте с консервативных настроек** - постепенно увеличивайте агрессивность
2. **Мониторьте статистику** - следите за success rate и retry rate
3. **Используйте прокси** - особенно для больших объемов данных
4. **Сохраняйте логи** - для анализа и оптимизации
5. **Планируйте ресурсы** - учитывайте время на капчи и ошибки

## Безопасность и этика

- Соблюдайте robots.txt и условия использования
- Не перегружайте серверы чрезмерными запросами  
- Используйте собранные данные ответственно
- Уважайте авторские права на контент

## Поддержка

При возникновении проблем:

2. Убедитесь в корректности настроек
